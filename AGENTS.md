# AGENTS.md

`@divmain/sat` — a zero-dependency SAT solver library (TypeScript, ESM, Node).

## v3 release: read the plan first

The v3 CDCL core and the full 3.0 public API (rich results, conflict budgets, async solving, incremental `add()`, cardinality constraints) are implemented. Release/final acceptance is tracked by **Janus plan `plan-d285`** — the full design doc lives at `.janus/plans/plan-d285.md`, and it supersedes the completed v2 plan `plan-7748` (release-validated at `ae1a4fe`, kept for historical reference). Code comments referencing "Design § ..." point into `plan-d285.md`. Work items are Janus tickets (`.janus/items/`); check plan status before picking up work, and keep every task checkpoint green. The quarantined v1 solver (`src/legacy.ts`) was deleted at the v2 API-rewire task (task-e476); do not resurrect v1 entry points.

Module layout:

- `src/expr.ts` — frozen formula frontend (`and`/`or`/`not`/`implies`/`xor` plus cardinality constructors `atMostOne`/`atMost`/`atLeast`/`exactly` with safe-integer `k` validation and multiset operands, `Value`, identity-memoized `getVariables`)
- `src/compile.ts` — Tseitin compiler, `BooleanExpr → CompiledCnf`: canonization (identity memo + structural hash-consing with multiplicity/order-preserving keys, same-kind flattening, total constant folding after variable collection, all compilation-scoped and non-mutating on caller ASTs) then emission (plain-clause carve-out, one aux per distinct canonical gate; conjunctive cardinality dispatches on the node — pairwise for k=1 with n≤6, Sinz sequential counter otherwise, `atLeast(k,L)` as `atMost(n−k, ¬L)` — and nested thresholds reify through a fully bidirectional Bailleux–Boufkhad totalizer, `atLeast(k) ⇔ u_k` / `atMost(k) ⇔ ¬u_{k+1}`); full structural validation of hand-built ASTs (exactly-one operator key matching `in`-dispatch, array payloads, cycle detection) precedes variable collection; the shared `compileDelta` engine backs both `compile()` (empty base: all names sorted into `0..k-1`) and `compileIncremental()` (the `SatSolver.add()` staging entry: known names keep their indices, new names sort within the batch and append after ALL existing indices including auxes, new auxes continue from there); literal helpers (MiniSat-style `lit = 2*v + isNeg`) live here; `solver.ts` imports them, never the reverse
- `src/solver.ts` — iterative CDCL core: watched propagation with blocker-literal watch entries (each entry caches the clause's current other watch; cross-linked twin entries keep both lists in step on relocation, audited per visit under debug assertions) plus dedicated binary-clause watch lists drained first (implicit propagation), first-UIP learning/backjumping with iterative recursive minimization and `rootBasis` dependency provenance (only base-derived root literals drop), VSIDS/phase saving, extracted restart policy units (`EmaRestartPolicy` default — lifetime fast/slow LBD averages, interval 32, ratio 1.25, 32-conflict blocking postponement — plus the internally selectable `LubyRestartPolicy` behind `restartPolicy: 'luby'`, configured by `restartBaseConflicts`), two-tier (glue LBD≤2 / reducible LBD>2) learned-clause reduction with decayed clause activity (`claInc *= 1/0.999` per round) and Glucose-style dynamic LBD tightening on analysis reuse (distinct non-zero levels; hysteresis applies improvements of ≥2 only, never increases), persistent enumeration, and replayable per-call assumption prefixes. Non-throwing call-scoped conflict budgets (`conflictBudget`, replacing the retired throwing `maxConflicts`) surface exhaustion through the resumable core as `'unknown'` after the final atomic conflict transaction — verdict > abort > budget, with the explicit budget-zero startup-propagation exception (once per call, never between enumeration models). The async drivers slice by `yieldQuantum` and yield through a platform-neutral chain (`globalThis.scheduler?.yield` → one-owned-`MessageChannel`-per-yield with both ports closed → `setTimeout(0)`); the internal `setYieldScheduler` test seam mirrors `setDebugAssertions` and is never re-exported. Incremental `add()` conjoins staged `compileIncremental` deltas into a live handle: failure-atomic (staging throws before any state mutates), quiescence-guarded (busy async/reentrant/in-flight-slice states throw), with a `named` `Uint8Array` flag replacing the contiguous `index < numNamedVars` invariant everywhere (appended batch indices follow the auxes, so named indices need not be contiguous), `ensureCapacity` reallocate-and-copy growth for all per-variable structures (new named vars enter the heap at activity 0 / FALSE), solver-owned growable `nameToIndex`/`indexToName` (the caller's CompiledCnf stays immutable), one root cancellation that preserves pending retained-root scans, and permanent-path batch admission (root-aware watches, base-derived root units at mask zero, root falsification cached as the startup conflict → `permanentUnsat`) with no re-preprocessing; add-time root work lands in the lifetime ledger only, excluded from per-call stats by their entry snapshots
- `src/index.ts` — exact public API: selective formula/type exports (including the four cardinality constructors), `SolverStats`/`SolverStatsInput`/`SolveResult`/`EnumerateResult`/`VariablePriority` plus `createSolverStats` (all defined in `solver.ts`), `SolveOptions`/`AsyncSolveOptions`/`SatSolverCallOptions`/`SatSolverAsyncOptions`/`SatSolver` (with `solve`/`solveAsync` plus incremental `add`/`variables`), `getSolution`, `getSolutionAsync`, `getAllSolutions`, `getAllSolutionsAsync`, and `createSolver`. Every entry point returns rich results (`SolveResult`/`EnumerateResult`; `'unknown'` is produced only by conflict-budget exhaustion or an abort signal), and UNSAT solves carry sound failed-assumption cores extracted per Design § UNSAT Cores. `Solver`, `getVariables`, `isVariable`, and compiler instrumentation such as `compileCount` stay internal

## Platform neutrality and debug audits

- **`src/` stays platform-neutral**: no bare `process` reference and no `node:` import anywhere under `src/`, and no DOM globals (`window`/`document`/`localStorage`/…) even in comments. Both type gates pin `lib` to `es2022` with no DOM/WebWorker typings: `tsconfig.json` for the build and `--lib es2022` on the `typecheck` script (unpinned, tsc defaults to the target's full lib set, which includes DOM). `test/platform-guard.spec.ts` enforces all of this — text scans plus both config pins — and allows exactly one platform reference by exact string: the guarded `globalThis.process?.env?.SAT_DEBUG === '1'` initialization in `src/solver.ts`. Do not add a second one; use a platform-neutral API instead. `AbortSignal` typing does NOT come from the DOM lib: `src/solver.ts` declares the minimal `readonly aborted` slice via `declare global`, which ships in `dist/solver.d.ts` and merges with the full DOM/Node declarations wherever a consumer's program provides them, so the packed declarations resolve with `types: []` and no DOM lib.
- **Debug audits are opt-in.** The audit flag initializes from `SAT_DEBUG=1` (read once at module load through the guarded access above); `setDebugAssertions(enabled)` — exported from the internal `src/solver.ts` only, never re-exported from `index.ts` — flips it at runtime, and audits read the flag at call time.
- **The test suite runs audits globally** via `--import ./test/debug.ts`, wired into every npm test script (Node propagates `--import` to `node:test` workers). Never import `test/debug.ts` from a spec file: the preload sets a `globalThis` load-proof marker that the guard test asserts, so the marker must be attributable to the preload alone.

## Commands

- `npm ci` — install the locked development tools in a fresh checkout
- `npm test` — full suite (`node:test` via tsx, discovers `./test/**/*.spec.ts`, prints coverage); allow several minutes for the unchanged 59,049-model enumeration stress, not a 120-second tool timeout
- `npx tsx --test './test/compile.spec.ts'` — single test file; put `--test-name-pattern '<name>'` before the file argument for one test
- `npm run check` — biome lint + format check; `npm run fix` — auto-apply
- `npm run build` — `tsc` (compiles `src/` only; tests are tsx-run, not compiled)
- `npm run bench` — the v3 candidate harness (`test/bench-v3.ts`, supported by `test/bench-v3-corpus.ts`, `test/bench-v3-adapter.ts`, `test/bench-v3-references.ts`, and `test/bench-evidence.ts`). Authenticates the sealed references exclusively from pinned Git bytes — the v2 baseline `test/v3-baseline.json` and `test/legacy-compiled-cnf.json` at artifact commit `cd44ed1`, their embedded source/tool provenance at pristine-v2 commit `ae1a4fe`, and the frozen recorder overlay at seal commit `2ba0a39` — then regenerates the pinned 23-row corpus (random 3-SAT n∈{150,200,250}×seeds{1,2,3}, PHP(9,8), XOR chains {8,12,16}, coloring {40,60}×{3,4}×{1,2}, the 32-call incremental history, `pairs(8)` enumeration), verifies immutable scenario identities/caps before any result comparison, and measures the candidate once per scenario at the baseline's calibrated cap. **Writes only `test/v3-benchmark.json` (canonical) and `test/v3-benchmark.md`** on success; the prose narrative in `test/v3-benchmark-review.md` is committed by hand and never rewritten by harness runs. Modes: **gates** (the default since learned-clause minimization ended the initial parity window) keeps immutable-input/outcome/cap/verdict checks and discloses algorithmic deltas; **parity** (`--parity`) hard-fails on any behavioral mismatch, including compiled snapshots and model digests, and is retained for explicit parity experiments. Runs at release gates and on demand (a full run takes roughly a minute), not per-commit CI.
- `npm run bench:legacy` — assert-only legacy benchmark verifier; **writes nothing**. Authenticates the frozen Phase-1/2/3 references plus the Phase-4 record, markdown, and manifest at the release commit, including every embedded Phase-4 source fingerprint against those Git bytes; re-runs all 8 fixtures; and compares the current compiler's **complete canonical compiled snapshot** (normalized clauses, `numVars`, named index/name universe, `levelZeroUnsat`) per fixture against the authenticated pristine-v2 `test/legacy-compiled-cnf.json` — this gate exists before any compiler-changing work and stays strict. Two modes: **gates** (the permanent default since the Phase-2 minimization task) keeps the same authentication/verdict/oracle/cap checks and prints non-fatal counter deltas; **parity** (`--parity`) hard-fails unless all 48 counters exactly equal the frozen Phase-4 record and is retained for explicit parity experiments. Source/fixture hashes identify measurements; recorded HEAD is context only.
- `npm run typecheck` — strict source/test typecheck (`tsc --noEmit --module ESNext --moduleResolution Bundler --target es2022 --lib es2022 --strict --exactOptionalPropertyTypes --noUnusedLocals --noUnusedParameters --skipLibCheck src/*.ts test/*.ts`; the ordinary build compiles source only)

- `test/v3-baseline-overlay/` is a frozen v2-era recorder sealed at commit `2ba0a39`: never edit, migrate, format, or import it (nothing outside that directory may import it; it contains no `*.spec.ts` by design). `test/v3-baseline.json`, `test/legacy-compiled-cnf.json`, the Phase-1/2/3/4 artifacts, reviews, and the release manifest are likewise immutable once committed; both harnesses read them **only** through authenticated Git bytes, never the mutable working tree.

## Packaging and CI

- `package.json` consumer contract (pinned by `test/release-smoke.mjs`): pure-ESM `exports` mapping only `"."` (no deep imports), `types`, `sideEffects: false`, `files: ["dist"]`, `license: "MIT"` backed by the root `LICENSE` file (npm auto-includes it in the tarball; the smoke test pins both the field and exactly one root `LICENSE`), real `description`/`keywords`/`repository`/`homepage`/`bugs`, empty `dependencies`, and intentionally no `engines` (not a claim of testing every Node version). Any task changing a smoke-pinned contract — metadata, the `dist/` inventory (`.js`/`.d.ts`/`.js.map`, never `.d.ts.map`), result shapes, the README fence inventory, or version — updates the smoke tooling in the same change.
- `tsconfig.json`: `strict: true`, emitting `sourceMap` + `inlineSources` (self-contained `.js.map` files) and deliberately **no `declarationMap`** — under `files: ["dist"]` its `../src` references would dangle.
- `.github/workflows/ci.yml` checks out with `fetch-depth: 0` (tests and benchmarks authenticate Git history), then runs `npm ci`, build, check, typecheck, the full test suite, and `bench:legacy`. CI deliberately runs `bench:legacy` only — the v3 candidate harness (`npm run bench`) runs at release gates and on demand, not per commit.

## Conventions that differ from defaults

- **`.js` extensions on relative imports in `src/`** (e.g. `from './expr.js'`) — tsconfig uses `module: NodeNext`; extensionless imports emit broken ESM into `dist/`.
- **`exactOptionalPropertyTypes: true`** — declare optional options properties as `foo?: T | undefined` or forwarding `opts?.foo` fails to typecheck.
- **Biome gates** (`npm run check`): no non-null assertions without a per-line `// biome-ignore ... : <reason>`; optional chaining required; no `any`; builtins imported as `node:assert`/`node:test`; `import type` for type-only imports. Bitwise ops, classes, and parameter reassignment are allowed.
- Machine-written JSON under `test/` must be `JSON.stringify(data, null, 2) + '\n'` or biome format-check fails.
- Test helper/tooling files must **not** match `*.spec.ts` (test discovery pattern) — see `test/helpers.ts`, `test/debug.ts`.
- `noUnusedLocals`/`noUnusedParameters` are on: defer fields to the phase that uses them, or `_`-prefix intentionally unused params.

## Hard constraints (from the plan — verify there before deviating)

- **Zero runtime dependencies, permanently** — PRNG, DIMACS parsing, benchmarking are hand-rolled in `test/`.
- **No recursion in `solver.ts`** (search depth must not hit the JS stack); compiler recursion over expression nesting is accepted.
- **No wall-clock assertions in unit tests** — performance is proven via `SolverStats` oracles (e.g. `decisions === 0`, `learnedClauses > 0`), never timers.
- Keep fixed fixtures/property batteries/stress sizes/conflict caps; the hypergraph oracle is **2 decisions, 16 propagations, 0 conflicts** (batch PLE leaves two ordinary named don't-cares), not zero decisions. PHP(7,6)/(8,7) benchmark caps remain **7230/36270**; a budget exception is a failure, never UNSAT evidence. Preserve frozen Phase-2/3 artifacts and expose regressions honestly.
- Determinism: sorted variable indexing (sorted initially, and sorted within each `add()` batch appended after all existing indices — deterministic but history-dependent), index-ordered tie-breaking, fixed default polarities.
- Pure-literal elimination is scoped to single-shot `getSolution`/`getSolutionAsync` only — enabling it for enumeration or incremental solving is unsound (pinned in Design § Design Principles and Hard Constraints; the `(v∨a)` counterexample is recorded in `src/index.ts`).
- Incremental assumptions are validated/snapshotted before cached UNSAT, replayed before decisions **and SAT**, and cancelled in `finally`. Call-local UNSAT must never poison the permanent base-UNSAT cache. Stats outputs reset before validation: per-call work/new learned admissions plus the absolute live learned count; retained lifetime core accounting/reduction cadence is separate. Initial units are enqueued during creation, outside incremental per-call measurements.
